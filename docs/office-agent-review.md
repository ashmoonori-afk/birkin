# Office 에이전트 구현과 남은 인수 항목

2026-09-08 기준 구현 리뷰다. 코드와 로컬 검증, 실제 계정 또는 사람이 확인해야 하는 항목을 구분한다. Microsoft 365 연결 시험은 마지막 순서로 유지한다.

## 구현된 경로

- Windows·macOS·Web의 주요 탐색을 대화·리서치·문서·승인으로 재구성하고 같은 Birkin BI를 적용했다. 보고서는 실제 대화 결과를 읽기 전용으로 표현하며, 문서·승인은 기존 실행 권한과 상태를 사용한다. [화면·접근성 인수 기준](ui-redesign-spec.md)을 별도로 기록했다.
- Native에서 문서를 가져와 검사하고 변경 내용을 승인한 뒤 파일과 검증 영수증을 저장한다. 자연어 도구로 만든 작업도 별도 diff ID 없이 기존 승인·작업 ID로 영수증을 표시한다.
- 메일 내용·첨부·계정과 승인 권한을 결속한다. 발송 결과가 불확실하면 같은 승인으로 원격 상태만 재확인하며, 재검토가 필요한 상태에서 자동으로 다시 발송하지 않는다.
- 일정의 다음 페이지, 시작 격자, 종일 날짜와 브리핑 시간대를 처리한다. 문서 가져오기·검색·팀 검토는 검증된 계정과 문서 버전에 결속한다.
- 업무 목록의 예정·상세·수정·완료, 파일별 배치 복구와 Windows 설치 교체 실패의 이전 버전 복원을 연결한다.
- `research_run`은 공개 원문 수집, 조사 축별 분석, 후속·반증 탐색, 주장별 감사를 수행한다. 최종 출처는 최대 18개이며 초기 수집 36회와 후속 탐색의 제한은 별개다. 출처의 사실과 전제·가정에 기반한 추론을 구분한다.
- 내부 Codex CLI와 상주 세션은 지시문을 사용자 입력에서 분리하고 임시 실행으로 처리한다. 내부 실행마다 사용자 Codex 작업 목록에 시스템 문구가 쌓이는 경로를 수정했다.
- 공급자와 Graph HTTP 요청은 자동 리디렉션을 따르지 않는다. Graph 문서 다운로드의 한 차례 HTTPS 전환에는 인증 헤더를 전달하지 않는다. RSS·XML 파싱에는 기존 DTD·엔티티 금지 검사를 재사용해 UTF-16 우회를 차단한다.

## 확인한 범위

- 기존 Codex 계정으로 대표 DOCX의 자연어 검사 → 승인 요청 → Native 승인 → 저장 → 영수증 경로를 한 번 끝까지 통과했다. 승인 전에는 결과 파일이 없었으며 저장된 두 수정 문단과 나머지 본문 보존을 직접 확인했다.
- Native WPF 테스트는 Protocol 137개, Shell 185개, App 123개가 통과했다. 별도 인수 실행을 요구하는 App 시험 3개는 기본 실행에서 건너뛴다. WPF 이미지 검사는 실제 Office 페이지 렌더나 Narrator 낭독을 대신하지 않는다.
- 별도 대표 파일에서 실제 Excel 재계산과 PowerPoint 렌더를 확인했다. 임의의 파일·수식·레이아웃 전체가 통과한 것은 아니다.
- Codex 지시 분리·임시 세션·멀티턴 문맥·로컬 작업 비저장 검증은 저장소와 설치본에서 각각 7개 조건을 통과했다. 다른 이번 변경의 전체 설치본 배포 완료를 의미하지 않는다.
- 고난도 CSV·Excel 연구의 최신 실제 실행은 일부 완료다. CSV 문법과 저장·재열기 위험의 문서 근거 범위는 충족했으나 아래 답변 품질 항목은 남았다. 모델 호출 성공이나 인용 형식 검사는 답변 전체의 정확성을 보증하지 않는다.
- 최신 실행은 Python 파일 621개의 해시를 유지한 채 904.6초에 끝났으며 모델 호출 51회가 성공했다. 출처 18개, 주장 32개 중 출처 뒷받침 11개·근거 기반 추론 3개·미확정 18개를 남겼다. 인용·본문 해시·전제 ID 구조 검사는 통과했지만 전체 답변 인수는 통과하지 못했다.
- 별도 실제 native-web 진단에서 한 번의 정상 검색 호출이 검색어 4개를 반환하는 것을 확인했다. 단일 검색어만 허용하던 검사를 검색어별 500자·최대 4개로 수정하고 실제 검색어 전체를 보존한다. 검색 호출 수·도구 종류·완료 순서 검사는 유지한다.
- 수정 후 실제 native-web 검색은 44.75초에 후보 15개를 반환했고, 중복을 제거한 9개 URL 모두 기존 수집 경로로 본문을 확보했다. Microsoft의 BOM·선행 0·긴 숫자 문서도 포함한다. 이 개별 진단은 전체 연구 답변의 통과를 대신하지 않는다.
- 추론 전제 ID는 검증된 사실 원장의 ID만 선택하도록 생성 스키마에 결속했다. 생성 상한에 닿은 불완전 문장과 감사 설명은 미확정으로 남기며, 최종 완전성 검토는 사용자가 요구한 설계 제안과 실제 실험 수행을 구분한다.
- 최신 답변에서 BOM 문서를 확보하고도 늦게 생성된 주장이 감사 상한 밖으로 밀리는 문제가 드러났다. 상한 24개는 유지하면서 새 출처 우선·조사 축별 배분으로 수정했다. 같은 실행 원장을 재배분하면 해당 BOM 주장이 선택되는 것을 확인했으며, 이 구조 검사가 전체 답변의 재감사를 대신하지는 않는다. OWASP 후보 수집과 문서 범위에 한정된 숫자·시점 주장의 판정은 별도 과제다.
- OWASP 후보는 기존 검색 대기열 뒤에도 같은 URL이 있어 우선순위를 받지 못했다. native 후보를 앞쪽으로 옮기고 기존 대기 항목을 제거하도록 수정했다. 부모가 이전 커밋에서 회귀 실패, 수정본에서 정확한 URL과 앞뒤 공백 URL 두 경우의 통과를 확인했다. 실제 재실행에서 OWASP 본문 수집과 답변 품질까지 확인해야 한다.
- 문서 귀속 진술은 원문 인용과 감사에서 지정 출처·범위를 확인했을 때만 별도 상태로 표시한다. 문서 내용을 실제 제품의 현재·보편 동작으로 단정하는 주장에는 기존 독립성·반증·최신성 기준을 유지한다. 문서 진술을 전제로 한 추론도 귀속 범위를 유지해야 하며, 감사 재시도와 최종 완전성 검토에 같은 제한을 전달한다. 구조 회귀와 실제 답변 품질 검증은 별개다.
- Windows 비교 검증은 새 문서 화면에서 변경 값을 확인한 뒤 승인 화면에서 실행하는 동선으로 보완했다. 고정 폭 때문에 겹치던 변경 전·후 라벨은 내용에 맞춰 폭을 정한다. 부모가 PNG에서 두 행의 라벨과 값이 겹치지 않는 것을 확인했고, Release LiveBridge 3개와 관련 diff·projection 6개가 통과했다. 기존 검토 패널의 CI 가시성 실패는 기록에 남기며, 수정 후 CI를 다시 확인해야 한다.
- macOS AppKit 캡처에서 대화·문서·승인·좁은 리서치 화면을 직접 확인했다. 기존 캡처 대체 이미지는 해소됐지만, 좁은 화면의 세로 여백과 승인 화면 상단 잘림이 드러났다. 세로 상태 카드의 불필요한 Spacer를 제거하고, 화면 증거는 실제 ScrollView·입력창을 사용하는 구성으로 수집한다. 터미널 OCR은 실제 한국어 제목을 확인하며, 수정된 화면의 CI 이미지 재검토는 남아 있다.
- 최종 HTTP·XML·M365 모킹·파일 복구 회귀는 313개 통과, 심볼릭 링크 권한이 없는 Windows에서 5개 건너뜀이다. Ruff는 통과했다. Bandit 중간 이상 심각도 경고는 이전 커밋의 15개에서 11개로 줄었고 새 경고는 없다. 전체 테스트나 보안 경고 전체 해소를 뜻하지 않는다.
