# 전체 클라이언트 UI 재설계

Windows·macOS·Web 전체를 대상으로 하는 구현·인수 기준이다. 기존 Python 승인·실행·복구 권한과 실제 연결 상태를 유지하면서 정보 구조와 시각 표현을 재설계한다.

## 공통 경험

- 왼쪽 탐색은 **대화 / 리서치 / 문서 / 승인**과 최근 업무를 중심으로 구성한다. 업무 만들기·전환·이름 변경·후속 업무는 기존 명령으로 연결한다. 부가 기능은 이름이 있는 더보기 또는 상세 영역에서 접근 가능하게 유지한다.
- 상단에는 Birkin, 현재 업무 제목과 실제 상태, 보기 전환을 표시한다. 연결 실패는 조치가 있는 안내로 보여준다. transport·cursor·reset 같은 내부 진단은 기본 화면 대신 펼칠 수 있는 상세에 둔다.
- 중앙은 선택한 업무의 작업 공간이다. 대화에는 읽기 편한 메시지와 입력창, 리서치에는 결론·근거·미해결을 읽는 보고서, 문서에는 가져오기·미리보기·변경 검토, 승인에는 결정해야 할 요청을 표시한다.
- 우측 검토 영역은 선택한 작업의 근거·변경·승인·실행 결과를 연결한다. 좁은 화면에서는 한 번에 한 주요 영역을 보여주고, 숨긴 영역을 키보드로 다시 열 수 있게 한다. 중첩 스크롤과 기본 표시되는 빈 위젯을 줄인다.
- 승인 전 변경 내용·대상·저장 위치·덮어쓰기·위험·유효 상태를 확인할 수 있어야 한다. 접수, 실행, 완료, 일부 완료, 결과 불확실을 구분하고 완료 뒤 실제 산출물·검증·영수증을 찾을 수 있어야 한다.
- 실제 제공하지 않는 기능을 버튼이나 숫자로 꾸미지 않는다. 빈 상태에는 현재 상태와 실행 가능한 다음 행동을 쓴다. 대화 기록을 숨긴 개인정보 보호용 캡처의 빈 화면을 제품 결함으로 해석하지 않는다.

## 공통 시각 체계

BI는 문서의 접힘을 형상화한 청록색 `b` 마크다. [원본 이미지](assets/birkin-brand-mark.png)를 Windows·macOS·Web 헤더와 README에서 재사용한다. 앱에서는 36–40px 마크와 Birkin 이름을 함께 표시하며, 이미지가 없어도 이름과 주요 탐색을 읽을 수 있게 한다.

차분한 밝은 업무 화면을 기본 방향으로 삼는다. 바탕 `#F4F6F8`, 문서·카드 `#FFFFFF`, 보조 표면 `#EEF2F5`, 본문 `#17212B`, 보조 글자 `#536171`, 경계 `#D6DEE5`, 주요 행동 `#116A61`, 선택 배경 `#E1F2EE`를 사용한다. 기존 사용자 테마 선택과 플랫폼 고대비 모드는 유지하며, 어두운 표현이 필요하면 동등한 의미·대비를 보장한다.

표면을 작은 카드로 과도하게 쪼개지 않는다. 업무 제목 22–26, 영역 제목 16–18, 본문 14–15, 보조 12–13을 기준으로 한다. 8 단위 간격, 10–14 모서리, 36 이상 높이의 주요 조작을 사용한다. 위험·실패는 색과 텍스트를 함께 쓰고, 임의의 이모지나 장식 아이콘보다 플랫폼 기본 아이콘과 명확한 이름을 사용한다.

## 플랫폼 구현 경계

- Windows: 기존 WPF View·ShellPresentation·명령·AutomationId·레이아웃 단축키를 재사용한다. 문서 작업을 좁은 고정 높이 위젯에 가두지 않는다. 승인 알림 진입은 정확한 카드와 읽기 시작점으로 이동한다.
- macOS: 기존 SwiftUI 상태·명령·접근성 식별자를 재사용한다. 공통 탐색과 검토 경험을 native split view, toolbar, 키보드 동작에 맞춘다. 서명·빌드 통과와 실제 화면 관측을 구분한다.
- Web: 기존 HTML/CSS/JS와 workspace snapshot/SSE/approval API를 재사용한다. 메시지와 연구 보고서의 제목·목록·코드·표·HTTP(S) 링크를 안전하게 표현하고 raw HTML이나 임의 URL scheme을 실행하지 않는다. 닫힌 패널은 focus·접근성 트리에서 제외하며 Esc와 원래 위치로의 focus 복귀를 지원한다.
- 연구 결과를 source-backed, inference, unresolved 등으로 표시할 때 실제 결과의 표현만 사용한다. 파싱 실패나 빈 근거를 완료나 검증 성공으로 추정하지 않는다.

## 인수 기준

1. 세 플랫폼에서 같은 이름으로 주요 업무를 찾고, 대화→결과 검토→승인→실행 결과까지 기존 authority 경로를 통해 이동한다.
2. 대표 화면 1500×940, 1024×768, 좁은 화면에서 현재 상태·주요 행동·내용이 잘리지 않고 접근 가능하다. Web은 360px와 200% 확대도 확인한다.
3. 키보드만으로 탐색·입력·근거 링크·승인·닫기·복귀가 가능하다. 숨은 drawer에 focus가 들어가지 않고 streaming 내용을 화면 읽기 프로그램에 매번 전체 재공지하지 않는다.
4. 승인하지 않은 작업은 실행되지 않는다. 오류·만료·연결 끊김·일부 완료는 다음 행동을 제시하고 입력과 선택을 보존한다.
5. mock 데이터는 검증용 화면에만 쓴다. 실제 provider/M365 동작과 정적·로컬 테스트를 구분하고, M365 실제 계정 검증은 마지막에 진행한다.
6. 플랫폼별 관련 회귀와 CI, 대표 렌더를 부모가 직접 검토한다. 실제 macOS 렌더·Narrator 등 관측하지 못한 항목은 완료로 표시하지 않는다.
7. 구현·검증·남은 조건을 README 양쪽과 리뷰 문서에 반영하고 커밋·푸시하여 PR #88의 최종 변경과 일치시킨다.
